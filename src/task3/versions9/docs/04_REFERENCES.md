- ค่าสูงสุดที่คาดได้จาก N trial อิสระ: `√V · ((1−γ)·Φ⁻¹(1−1/N) + γ·Φ⁻¹(1−1/(N·e)))` (γ ≈ 0.5772)
  · ค่า `√(2 ln N)` ใน §4.3 คือรูปประมาณเมื่อ N ใหญ่
- N ต้องเป็น **จำนวน trial ที่อิสระกัน** · ภาคผนวก A.3 ประมาณ N ที่แท้จริงจากสหสัมพันธ์เฉลี่ยระหว่าง trial
- **ใช้กับ v9:** เราใช้ N = จำนวนสเปกที่ลองจริง ซึ่งสัมพันธ์กันสูง (v4 วัดได้ ρ 0.71–0.79) จึงหักมากเกินจริง = ระวังไว้ก่อน
  · ที่ N = 9–10 รูปประมาณ `√(2 ln N)` ≈ 2.1 สูงกว่าสูตรเต็ม (≈ 1.5–1.6) ยิ่งระวังขึ้นอีก

**Welch & Goyal (2008, RFS 21(4):1455–1508)** · อ่าน: บางส่วน
- ตัวทายผลตอบแทนตลาดส่วนใหญ่ out-of-sample แย่ และไม่เสถียรตามช่วงเวลา
- **ใช้กับ v9:** เหตุผลที่ต้องดู skill รายปี (§4.2) ไม่ใช่ค่ารวมอย่างเดียว

**Campbell & Thompson (2008, RFS 21(4):1509–1531) "Can anything beat the historical average?"** · อ่าน: บทคัดย่อ (DASH ไม่ยอมให้ดึง PDF)
- ตอบ Welch–Goyal: ถ้าบังคับเครื่องหมาย coefficient ให้ตรงทฤษฎีและไม่ให้ค่าทายผลตอบแทนติดลบ การถดถอยหลายตัวชนะค่าเฉลี่ยในอดีตได้
  · R² ที่ได้เล็ก แต่มีความหมายทางเศรษฐกิจ
- **ใช้กับ v9:** การจำกัดแบบนี้คล้ายโมเดลสำรอง κ (ดึงค่าทายเข้าหา 0) · ไม่ใช้การจำกัดเครื่องหมาย เพราะเราไม่มีทฤษฎีบอกเครื่องหมายทุก feature

**Rapach, Strauss, Zhou (2010, RFS 23(2):821–862) "Combination forecasts and links to the real economy"** · อ่าน: บทคัดย่อ (มหาวิทยาลัยไม่มีสิทธิ์เข้าถึง RFS)
- โมเดลเดี่ยวไม่เสถียร · เฉลี่ยค่าทายของหลายโมเดลชนะค่าเฉลี่ยในอดีตสม่ำเสมอ เพราะลดความแปรปรวนของค่าทาย
- **ใช้กับ v9:** สนับสนุนขั้น 7 และเหตุผลเดียวกับ Kelly (ขนาดค่าทายที่แกว่งเกินทำให้ MSE แย่)

**Cerqueira, Torgo, Mozetič (2020, Mach. Learn.) "Evaluating time series forecasting models"** · arXiv:1905.11744 · อ่าน: บางส่วน
- 62 อนุกรมจริงที่ไม่นิ่ง: วิธีที่รักษาลำดับเวลาประมาณ error ได้แม่นกว่า cross-validation · ดีสุดคือ holdout หลายจุดตัด (Rep-Holdout)

**Cerqueira, Torgo, Soares (2022) "Model Selection for Time Series Forecasting"** · arXiv:2104.00584 · อ่าน: บางส่วน
- 3,111 อนุกรม 50 โมเดล · ทุกวิธีเลือกโมเดลที่ดีที่สุดได้ถูกแค่ **7–10%** · เสียความแม่นเพราะเลือกผิด 0.28–0.58%
- **holdout จุดตัดเดียวแย่ที่สุด (0.58%)** · ผู้เขียนแนะนำให้เลี่ยงถ้าข้อมูลไม่มาก · อนุกรมสั้นกว่า 1,000 จุดเสีย 1.19%
- **ใช้กับ v9:** การเลือก hyperparameter ด้วย 20% ท้ายของหน้าต่างเทรน (§3) คือ holdout จุดตัดเดียว (§7 ข้อเสนอ 2)
- *แก้จากที่ผมสรุปไว้ก่อนอ่าน:* ตัวเลข "1.2–2.3%" ที่เคยบอกผิด ตัวเลขจริงตามข้างบน

**Rossi & Inoue (2012, JBES 30(3):432–453) "Out-of-sample forecast tests robust to the choice of window size"** · อ่าน: บทคัดย่อ (มี PDF)
- ถ้าลองหลายขนาดหน้าต่างแล้วรายงานอันที่ดี จะเป็น data snooping · เสนอสถิติที่รวมทุกขนาดหน้าต่าง
- **ใช้กับ v9:** เราล็อกหน้าต่างขยายไว้แบบเดียวก่อนรัน จึงไม่เจอปัญหานี้ · ห้ามเพิ่มหน้าต่างเลื่อนทีหลังแล้วเลือกตัวที่ดีกว่า

## 7. ข้อเสนอ (ยังไม่ได้ทำ เจ้าของตัดสินก่อนล็อก)

1. **positive control (Mesfin 2026):** ก่อนรันบันได ฉีดสัญญาณที่รู้ขนาดเข้าไปในเป้า (เช่น `y + c·x` ที่ `x` คือ feature ปลอม)
   แล้วดูว่าไปป์ไลน์และ Clark–West จับได้ที่ขนาดเท่าไหร่ · ตอบคำถามเดิมของ v7 ว่าการออกแบบมองไม่เห็นผลต่ำกว่าเท่าไหร่
   · ไม่ใช้ข้อมูลจริงของช่วงยืนยัน จึงไม่นับเป็นสเปก
2. **การเลือก hyperparameter (Cerqueira 2022):** 20% ท้ายจุดตัดเดียวเป็นวิธีที่แย่ที่สุดในงานนั้น · ทางเลือกคือเฉลี่ย
   error บน holdout หลายจุดตัดในหน้าต่างเทรน · ต้องเปลี่ยน §3 ก่อนรัน มิฉะนั้นคงไว้แล้วรายงานข้อจำกัดนี้
3. **รายงาน Clark–West (Clark & West 2007):** เขียนว่าหน้าต่างขยายทำให้ขนาดทดสอบอาจคลาดเล็กน้อย · ไม่ต้องเปลี่ยนวิธี
4. **วัน XD (Elton–Gruber, Anantarak):** 03_FEATURES §1 มีแค่ตัวบอกวัน XD (0/1) · error จากราคาตกไม่เต็มปันผลมีขนาด
   ตามสัดส่วนปันผล `(1 − ratio) · D_d / C_{d−1}` ตัวบอก 0/1 จึงเรียนได้แค่ค่าเฉลี่ย · ถ้าจะใช้ `D_d / C_{d−1}` แทน ต้องแก้ก่อนรันขั้น 2
   · วัน XD มีแค่ไม่กี่วันต่อปีต่อหุ้น ผลต่อ RMSE รวมจึงเล็ก
5. **feature ที่มีทฤษฎีแต่ยังไม่มี (Heston–Korajczyk–Sadka, Bogousslavsky):** return ช่วงเดียวกันของเมื่อวาน และ return lag 5 วัน
   · การเพิ่มคือสเปกใหม่ ต้องนับตาม §3 · เสนอให้จดไว้เป็นงาน v9.1 มากกว่าเพิ่มตอนนี้

### 8.3 ปรับโมเดลไหม

**ปรับ (ตั้งก่อนรัน ไม่นับสเปก):**
1. **ridge: ขยาย α ถึง 10⁴** — `α ∈ 10^{−2, −1.5, …, 4}` (13 ค่า แทน 11)
   - feature ปรับสเกลแล้ว และ sklearn ใช้ loss แบบผลรวม (ไม่หาร n) · α ที่เหมาะเมื่อ coefficient เล็กเท่า ๆ กันคือราว `p / R²`
     · ถ้า p ≈ 15–25 และ R² ≈ 0.5–2% จะได้ราว 10³–5·10³ · grid เดิมหยุดที่ 10³ จึงอยู่ที่ขอบล่างของช่วงที่น่าจะดีที่สุด
   - Kelly และ Gu–Kelly–Xiu: สัญญาณอ่อน → shrink แรงช่วย · ถ้า α ที่เลือกยังชนขอบบน 10⁴ บ่อย แปลว่าโมเดลอยากให้ค่าทายเข้าใกล้ 0
2. **Huber: ใช้ช่วง α เดียวกับ ridge** — เดิม `10^{−4…0}`
   - `HuberRegressor` ของ sklearn ก็ใช้ loss แบบผลรวม · α ≤ 1 แทบไม่ shrink เลย ขั้น 3 จึงเป็น "OLS ที่ไม่ไล่วันสุดโต่ง" ไม่ใช่ "ridge ที่ทนวันสุดโต่ง"
   - ถ้าตั้งใจให้เป็นแบบแรก คงไว้ได้ แต่ต้องเขียนให้ชัดใน 02 §3

**เพิ่ม (ไม่บังคับ · 1 สเปก รอบบ่าย 8 → 9 ไม่เกินเพดาน):**
3. **OLS รอบบ่าย + พจน์ร่วม `r_morning × ช่วงราคา high–low ภาคเช้า`** — Gao พบผลแรงในวันผันผวนสูงและแทบไม่มีในวันผันผวนต่ำ
   · HGB จับได้เองอยู่แล้ว แต่สเปกนี้ตอบได้ตรงว่าผลมาจากตรงนี้ไหม · ถ้าไม่เพิ่ม ใช้การแยก 3 กลุ่มใน §8.2 เป็นรายงานแทน

**ไม่เปลี่ยน:**
- HGB ความลึก {2, 3} — Gu–Kelly–Xiu พบว่าต้นไม้ที่ดีมีไม่ถึง 6 ใบ
- MLP 1 ชั้น 16 หน่วย — NN ดีสุดแค่ 3 ชั้นแม้ข้อมูลใหญ่กว่าเรามาก
- ensemble เฉลี่ยเท่ากัน — forecast combination puzzle
- โมเดลสำรอง κ — สอดคล้องกับ Campbell–Thompson (ดึงค่าทายเข้าหาค่าที่ปลอดภัย)
- 1D-CNN คงไว้ตามที่เจ้าของให้รันทุกขั้น แต่ไม่ขยายเป็น LSTM/Transformer

**ไม่เพิ่ม (คงการตัดเดิม):** LSTM/Transformer (Zeng) · XGBoost/LightGBM (Grinsztajn: ใกล้ HGB) · ARIMA/GARCH (Hansen–Lunde: ทายความผันผวน ไม่ใช่ค่าเฉลี่ย)
