## 1. สรุปสั้น

- ทาย **2 หุ้น** (KBANK, ADVANC) **วันละ 2 รอบ**
  - **รอบเช้า:** ส่งก่อน **09:30** ทายราคาปิดภาคเช้า `P_d`
  - **รอบบ่าย:** ส่งก่อน **13:00** ทายราคาปิดทางการ `C_d`
- วันสอบจริง: **จ. 2026-11-09 → ศ. 11-13** ต้องส่งครบ 2 × 2 = 4 ค่าทุกวัน (รวม 20 ค่า)
  ค่าที่บันทึกหลังเวลาตัดไม่นับ จึงต้องเก็บเวลาที่บันทึกไว้ทุกครั้ง
- **ใช้ volume ไหม: ใช้ ทั้งสองรอบ** (ดูข้อ 3)
- รอบเช้าใช้ **Huber regression แยกหุ้น** ส่วนรอบบ่ายใช้ **HistGradientBoosting ตัวเดียวสำหรับทั้งสองหุ้น**
- ทั้งสองรอบมี **โมเดลสำรอง** (OLS ที่หดค่าทายลง) ใช้เมื่อ feature ของโมเดลหลักไม่ครบ

## 2. ทายอะไร

| สัญลักษณ์ | ความหมาย |
|---|---|
| `C_{d-1}` | ราคาปิดทางการเมื่อวาน |
| `D_d` | เงินปันผลต่อหุ้นที่ขึ้น XD วันนี้ (ไม่มี = 0) |
| `P_d` | ราคาปิดของแท่ง 1m สุดท้ายในภาคเช้าที่ `bar_end ≤ 12:30` |
| `C_d` | ราคาปิดทางการวันนี้ |

โมเดลไม่ได้ทายราคาตรง ๆ แต่ทาย **log return เทียบกับจุดอ้างอิง** แล้วแปลงกลับเป็นราคา

| รอบ | จุดอ้างอิง | โมเดลทาย | แปลงกลับเป็นราคา |
|---|---|---|---|
| เช้า | `anchor_m = C_{d-1} − D_d` | `ŷ ≈ log(P_d / anchor_m)` | `P̂_d = anchor_m · exp(ŷ)` |
| บ่าย | `P_d` (ราคาจริงตอน 12:30) | `ŷ ≈ log(C_d / P_d)` | `Ĉ_d = P_d · exp(ŷ)` |

**ตัวเทียบ** (ใช้วัดผล ส่งเป็นคำตอบไม่ได้) คือ "ราคาไม่ขยับ" หรือ `ŷ = 0`
รอบเช้าคือ `P̂ = C_{d-1} − D_d` ส่วนรอบบ่ายคือ `Ĉ = P_d`

## 3. ใช้ volume ไหม

**ใช้** มี feature ที่มาจาก volume 3 ตัว

| feature | ใช้ในรอบ | สูตร | ข้อมูลที่ต้องมี |
|---|---|---|---|
| `vol_prev` | เช้า + บ่าย | `log(V_{d-1} / ค่าเฉลี่ย V ของ 20 วันล่าสุดถึง d-1)` ต้องมีอย่างน้อย 15 จาก 20 วัน | **volume รายวันทางการ** ย้อนหลัง ≥ 20 วัน |
| `vol_am` | บ่าย | `log(volume ภาคเช้าวันนี้ / ค่าเฉลี่ย volume ภาคเช้า 20 วันก่อนหน้า)` ต้องมี ≥ 15 วัน | **volume แท่ง 1m** ภาคเช้า ย้อนหลัง ≥ 20 วัน |
| `vwap_gap` | บ่าย | `log(P_d / VWAP ภาคเช้า)` โดย `VWAP = Σ(close·volume) / Σ volume` | **volume แท่ง 1m** ภาคเช้าวันนี้ |

- โมเดลสำรองทั้งสองตัวไม่ใช้ volume
- bundle เก่าอย่าง v5 และ v5.3 ใน `src/task3/deployment/` ก็ไม่ใช้ volume
  (`volatility_20d` ใน v5 คือความผันผวนของราคา ไม่ใช่ปริมาณซื้อขาย)

**⚠️ เรื่องหน่วย:** feature volume ทุกตัวเป็นอัตราส่วนเทียบค่าเฉลี่ย 20 วัน หน่วยจึงหักล้างกันเอง
แต่ข้อมูลย้อนหลัง 20 วันกับข้อมูลวันนี้ **ต้องมาจากแหล่งเดียวกันและหน่วยเดียวกัน** (หุ้น ไม่ใช่ lot)
ถ้าใช้ volume จาก MT5 หรือ SET เป็นข้อมูลย้อนหลัง แล้วใช้ `volume_delta` ของ Oanor เป็นข้อมูลวันนี้ ค่าจะเพี้ยนทันที

## 4. โมเดลรอบเช้า (ส่งก่อน 09:30)

### โมเดลหลัก: Huber regression แยกหุ้น

- `sklearn.linear_model.HuberRegressor(epsilon=1.35, alpha=α, max_iter=2000)`
- α ที่ใช้ในปี 2026: **KBANK = 1000, ADVANC = 100**
- **feature 16 ตัว (KBANK) หรือ 15 ตัว (ADVANC):**
  `spx, thd, thb, n225, hsi, fut_post, on_prev, id_prev, range_prev, vol_prev, [peer_prev เฉพาะ KBANK], monday, gap_days, long_break, xd, atc_push`

### การเตรียมข้อมูลก่อนเข้าโมเดล (ทำซ้ำตอนทายจริงด้วยค่าจากชุดเทรน)

1. clip แต่ละ feature ให้อยู่ระหว่าง quantile 1% และ 99% ของชุดเทรน
2. ปรับเป็น z-score ด้วย mean และ SD ของชุดเทรนหลัง clip
3. เทรนบน `y / sd(y)` แล้วคูณ `sd(y)` กลับตอนทาย

### โมเดลสำรอง: `ols_atc`

- OLS มีค่าคงที่ แยกหุ้น ใช้ feature `spx, thd, thb, n225, hsi, atc_push`
- clip 1%/99% แต่ไม่ปรับเป็น z-score
- ค่าทาย `P̂ = anchor_m · exp(0.7 · ŷ_ols)`
- **ใช้เมื่อ** feature ตัวใดตัวหนึ่งของ Huber ไม่มี ส่วนใหญ่คือ `fut_post` (futures หลังตลาดปิด) หรือราคาหุ้นแบงก์

## 5. โมเดลรอบบ่าย (ส่งก่อน 13:00)

### โมเดลหลัก: HistGradientBoosting ตัวเดียวสำหรับทั้งสองหุ้น

- `sklearn.ensemble.HistGradientBoostingRegressor(learning_rate=0.05, min_samples_leaf=50, l2_regularization=1.0, max_depth=2, max_iter=28, early_stopping=False, random_state=340)`
  (`max_depth` และ `max_iter` ที่เลือกได้ในปี 2026)
- เทรนรวม KBANK กับ ADVANC ในตารางเดียว มีคอลัมน์ `is_kbank` (KBANK = 1, ADVANC = 0)
- **feature 24 ตัว:**
  `spx, thd, thb, n225, hsi, on_prev, id_prev, range_prev, vol_prev, monday, gap_days, long_break, xd, atc_push, r_morning, jump, r_last30, r_last60, vwap_gap, range_am, vol_am, post_2024, tick_dir, is_kbank`
- **ไม่ต้องใช้** ราคาหุ้นแบงก์, futures, ดัชนี SET หรือดัชนีกลุ่มอุตสาหกรรม
- clip 1%/99% ตามชุดเทรน ไม่ทำ z-score และไม่ scale y

### โมเดลสำรอง: `ols_small`

- OLS มีค่าคงที่ แยกหุ้น
  - KBANK ใช้ `r_morning, r_last30, peer_am`
  - ADVANC ใช้ `r_morning, r_last30`
- ค่าทาย `Ĉ = P_d · exp(0.5 · ŷ_ols)`
- KBANK ต้องใช้ราคาหุ้นแบงก์ตอนเที่ยง (`peer_am`) ด้วย

## 6. Feature ทุกตัว

`d` คือวันที่ทาย ส่วน `prev` คือวันซื้อขายก่อนหน้าตามปฏิทิน SET

| feature | สูตร | แหล่งข้อมูล | ข้อมูลพร้อมตอน (เวลาไทย) | volume |
|---|---|---|---|---|
| `spx` | `log(ราคาปิด S&P 500 ล่าสุดที่วันที่ ≤ d−1 / ราคาปิดล่าสุดที่วันที่ ≤ prev−1)` | Yahoo `^GSPC` | 03:00–04:00 | |
| `thd` | เหมือน `spx` แต่ใช้ ETF ไทย THD | Yahoo `THD` | 03:00–04:00 | |
| `thb` | เหมือน `spx` แต่ใช้ USD/THB (ใช้วันที่ตามเวลาลอนดอนของแต่ละแท่ง) | Yahoo `THB=X` | ~06:00 | |
| `n225` | `log(ราคาเปิด Nikkei วันนี้ / ราคาปิดล่าสุดที่วันที่ ≤ prev)` ถ้าตลาดปิดให้ใช้ 0 | Yahoo `^N225` | 07:00 | |

| `fut_post` | `log(fut_1655 / fut_1645)` ของ prev: `fut_1645` = ราคาปิดแท่ง 30m ที่เริ่ม 16:15, `fut_1655` = ราคาปิดแท่งที่เริ่ม 16:45 (TFEX ปิด 16:55) | TFEX S50 front month (TradingView `S501!`) | 17:15 ของ prev | |
| `on_prev` | `log(O_{d-1} / (C_{d-2} − D_{d-1}))` | OHLCV รายวันทางการ | 17:00 ของ prev | |

| `peer_prev` | ค่าเฉลี่ยของ BBL, KTB, SCB, TTB, KKP, TISCO ของ `log(ราคา ATC ของ prev / ราคา ATC วันก่อน prev)` | แท่ง 1m ของหุ้นแบงก์ 6 ตัว ช่วง `closing_label` | 16:40 ของ prev | |
| `monday` | 1 ถ้าวันนี้เป็นวันจันทร์ ไม่ใช่ให้เป็น 0 | ปฏิทิน | — | |
| `gap_days` | จำนวนวันตามปฏิทินจาก prev ถึง d | ปฏิทิน SET | — | |
| `long_break` | 1 ถ้า `gap_days ≥ 4` | ปฏิทิน SET | — | |
| `xd` | `D_d / C_{d-1}` | ประกาศ XD จาก SET | วันที่ประกาศ | |
| `atc_push` | `log(C_{d-1} / ราคาปิดแท่ง 1m สุดท้ายในช่วงซื้อขายต่อเนื่องภาคบ่ายของ prev)` คือแรงดันราคาช่วง ATC เมื่อวาน | ราคาปิดทางการ + แท่ง 1m | 16:40 ของ prev | |
| `r_morning` | `log(P_d / anchor_m)` | แท่ง 1m | 12:30 | |
| `jump` | `log(ราคาเปิดของแท่ง 1m แรกภาคเช้า / anchor_m)` | แท่ง 1m | หลังแท่งแรกของภาคเช้า | |

| `r_last60` | `log(P_d / ราคาปิดแท่ง 1m สุดท้ายที่ bar_end ≤ 11:30)` | แท่ง 1m | 12:30 | |
| `vwap_gap` | ดูข้อ 3 | **แท่ง 1m รวม volume** | 12:30 | ✔ |

| `vol_am` | ดูข้อ 3 | **แท่ง 1m รวม volume** | 12:30 | ✔ |

**แท่ง 1m:** ระบบตั้งชื่อแท่งตาม **เวลาจบ** (`bar_end`) ส่วน MT5 ตั้งตามเวลาเริ่ม (`bar_end = timestamp + 1 นาที`)
ภาคเช้านับแท่งที่ `bar_end` อยู่ระหว่าง 09:56 ถึง 12:30 และใช้เฉพาะแท่งที่จบแล้ว

## 7. ข้อมูลสดที่ต้องดึง

| ข้อมูล | ใช้กับ | ต้องมีก่อน | Oanor มีไหม |
|---|---|---|---|
| แท่ง 1m OHLCV ของ KBANK และ ADVANC (ภาคเช้าวันนี้ + ราคาปิด continuous ภาคบ่ายเมื่อวาน) | ทั้งสองรอบ | 12:30 (รอบบ่าย) | มีบางส่วน เป็น snapshot จากการ poll ไม่ใช่แท่งจริง |
| OHLCV รายวันทางการของ KBANK และ ADVANC ย้อนหลัง ≥ 21 วัน | ทั้งสองรอบ | 17:00 ของ prev | **ไม่มี** |
| ราคา ATC ของ BBL, KTB, SCB, TTB, KKP, TISCO (2 วันล่าสุด + ตอนเที่ยงวันนี้) | KBANK เช้า (โมเดลหลัก) และ KBANK บ่าย (โมเดลสำรอง) | 09:30 / 13:00 | **ไม่มี** |
| S50 futures แท่ง 30m ที่เริ่ม 16:45 ของ prev | เช้า (`fut_post`) | 09:30 | **ไม่มี** |
| Yahoo `^GSPC`, `THD`, `THB=X`, `^N225`, `^HSI` | ทั้งสองรอบ | 09:30 (ต้องมีราคาเปิด Nikkei และ HSI ของวันนี้แล้ว) | **ไม่มี** |
| ประกาศ XD + จำนวนเงินปันผล | ทั้งสองรอบ | ก่อน 09:30 | **ไม่มี** |
| ปฏิทินวันซื้อขาย SET | ทั้งสองรอบ | — | **ไม่มี** |

**ปัญหาของ Oanor ตอนนี้:**
1. มีแค่ KBANK และ ADVANC จึงไม่มีหุ้นแบงก์, futures และ Yahoo ถ้าไม่มี `fut_post` รอบเช้าต้องใช้โมเดลสำรองทุกวัน
2. ราคาได้จากการ poll ทุกนาที ไม่ใช่แท่ง 1m จากตลาด ค่า `jump`, `range_am`, `tick_dir`, `vwap_gap` จึงจะไม่ตรงกับตอนเทรน
3. `volume_delta` คำนวณจาก volume สะสม จึงต้องใช้แหล่งเดียวกันทั้ง 20 วันย้อนหลัง (ดูข้อ 3)
4. ไม่มีราคาปิดทางการหรือราคา ATC ที่ระบุชัด

## 9. ขั้นตอนแต่ละวัน

```
หลังตลาดปิด 17:15 (prev)    เก็บ OHLCV ทางการ, ราคา ATC หุ้นแบงก์, futures แท่ง 16:45
ก่อน 09:00                   ดึง Yahoo (spx, thd, thb) + เช็กประกาศ XD
08:30–09:25                  ดึงราคาเปิด Nikkei (07:00) และ HSI (08:30)
                             → สร้าง feature รอบเช้า
                             → ครบทุกตัว? ใช้ Huber : ใช้ ols_atc × 0.7
                             → P̂ = anchor_m · exp(ŷ) → บันทึกพร้อมเวลา (ก่อน 09:30)
12:30                        แท่ง 1m ภาคเช้าครบ → ได้ P_d จริง
12:30–12:55                  → สร้าง feature รอบบ่าย
                             → ครบทุกตัว? ใช้ HGB : ใช้ ols_small × 0.5
                             → Ĉ = P_d · exp(ŷ) → บันทึกพร้อมเวลา (ก่อน 13:00)
หลังตลาดปิด                  เก็บ P_d และ C_d จริงไว้วัดผล
ศุกร์หลังตลาดปิด             fit ใหม่สำหรับสัปดาห์หน้า + บันทึก hash ของโมเดล
```

ส่ง "ราคาไม่ขยับ" (ตัวเทียบ) เป็นคำตอบไม่ได้ ถ้าข้อมูลของโมเดลสำรองก็ไม่ครบด้วย ให้บันทึกว่าวันนั้นส่งไม่ทัน
