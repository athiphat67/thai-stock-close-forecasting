  คือ linear regression บน covariate = ซ้ำกับ ridge · Chronos-Bolt ไม่รับ covariate · ให้กลุ่ม C ตอบคำถามเดียว: "อนุกรมอย่างเดียวพอไหม"

### 1.1 C04 แท่งครึ่งวัน

- แท่งเช้าของ d: open = ราคาซื้อขายแรกของภาคเช้า · high/low ของแท่ง 1m ที่ `bar_end ≤ 12:30` · close = `P_d` · volume รวม ·
  amount = Σ(close × volume) ของแท่ง 1m
- แท่งบ่ายของ d: จากแท่ง 1m ภาคบ่าย · close = `C_d` (ราคาปิดทางการ รวม ATC)
- timestamp ที่ส่งให้ Kronos = เวลาปลายแท่ง (12:30 และ 16:30 ตามเวลากรุงเทพ)
- **รอบเช้า:** แท่งสุดท้ายใน context = บ่ายของ d−1 → ทายแท่งเช้าของ d · **รอบบ่าย:** แท่งสุดท้าย = เช้าของ d → ทายแท่งบ่ายของ d
- **XD:** ปรับราคาทุกแท่งก่อนวัน XD ด้วย `inputs.adjust_xd` ให้ close ของแท่งสุดท้ายก่อนทายเท่ากับ anchor (`C_{d−1} − D_d`)
- ก่อน 2017-04 ไม่มีแท่ง 1m → แท่งครึ่งวันเริ่ม 2017-04 · ถึง 2019-01 มีราว 850 แท่ง > 512 พอ

## 2. ข้อมูลรั่วจากการ pretrain (สำคัญที่สุดของกลุ่มนี้)

- weight ทุกตัวฝึกจากข้อมูลจริงก่อนวันปล่อย · **ข้อมูลหุ้นช่วง 2019–2025 อาจอยู่ในชุดฝึก** โดยเฉพาะ Kronos ที่ฝึกจากแท่งเทียน 45 ตลาด
  (อาจรวม SET) → คะแนนก่อนวันปล่อยอาจดีเกินจริง
- จดวันปล่อยและช่วงข้อมูลฝึกจาก model card ลง `run_manifest.json` ก่อนรัน (ค่าคาดการณ์ ต้องยืนยัน: Chronos-Bolt 2024-11 ·
  Moirai 2.0 2025-08 · Kronos 2025-08 · TimesFM 2.5 2025-09)
- **รายงานแยก:** (ก) ทั้งช่วงตามปกติ (ข) **เฉพาะวันหลังวันปล่อยของแต่ละตัว ถึง 2026-09-04** = ช่วงที่สะอาดของตัวนั้น
  · ข้อสรุปของกลุ่ม C ให้ใช้ (ข) เป็นหลัก · ถ้า (ก) ดีกว่า (ข) ชัดเจน ให้เขียนว่าน่าจะมาจากข้อมูลรั่ว
- กลุ่มอื่นไม่มีปัญหานี้ เพราะเทรนเองบนหน้าต่างที่ตัดแล้ว

## 3. ความทำซ้ำได้และอุปกรณ์

- รันบน CPU เป็นค่าเริ่มต้น · ถ้า C02/C04 ช้าเกิน 1 ชั่วโมงต่อรอบ อนุญาต MPS · จดอุปกรณ์ใน manifest
- C03, C04 สุ่ม: ตั้ง `torch.manual_seed(340)` ก่อนทายแต่ละ batch · รันซ้ำบน 20 วันแรกต้องได้เท่าเดิม (บน CPU)
- ทายเป็น batch: ทุกวันของหุ้นหนึ่งในหนึ่งปี = 1 batch (context ต่างกันรายวัน)
- เวอร์ชันแพ็กเกจและ hash ของ weight จดใน manifest · ห้ามอัปเดต weight ระหว่างรัน

## 4. test เพิ่ม

1. context ของวัน d ไม่มีค่า `y` ของวัน d (เช้า) · C04 รอบบ่าย: แท่งสุดท้ายใน context = แท่งเช้าของ d และไม่มีแท่งบ่ายของ d
2. แท่งครึ่งวันตรงกับ `P` และ `C` ใน feature store ทุกวัน (ก่อนปรับ XD)
3. ใส่อนุกรมคงที่ (ทุกค่า = 0.001) → C01–C03 ทายใกล้ 0.001 (ตรวจว่าเรียก API ถูกหน่วย)

## 5. positive control (ปรับให้เข้ากับโมเดลที่ไม่เห็น feature)

- ฝังความสัมพันธ์ที่**มองเห็นได้ในอนุกรม**: `y_c(d) = y(d) + φ·y_c(d−1)` · φ ตั้งให้ส่วนที่ทายได้อธิบายราว 2% ของความแปรปรวน
  (φ ≈ 0.14) · C04 เลื่อนทั้งแท่งด้วยตัวคูณ `exp(y_c − y)`
- ให้คะแนน 2021–2022 · ผ่าน = skill บน `y_c` ลบ skill บน `y` ≥ 1%
- ตัวที่ไม่ผ่าน = "zero-shot ไม่จับ AR(1) ขนาด 2%" ซึ่งเป็นข้อมูลอธิบายผลหลักได้ดี
